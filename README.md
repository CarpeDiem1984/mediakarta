# Медиакарта

Мини-CRM журналистов для PR-отдела. Здесь собраны издания, журналисты, заметки, инфоповоды и медиалисты. Вход по логину и паролю, у каждой заметки и каждого питча есть автор.

- **Интерфейс** лежит в этом репозитории и открывается через GitHub Pages.
- **Данные и логины** хранятся в Supabase (бесплатный тариф).
- В репозитории нет ни одного контакта. Базы журналистов сюда не загружаются никогда.

Пока в `js/config.js` пусто, приложение работает в **демо-режиме** на тестовых данных. Так удобно посмотреть интерфейс до подключения базы.

## Запуск с нуля (≈20 минут, один раз)

### Шаг 1. База данных в Supabase

1. Зайдите на [supabase.com](https://supabase.com) → **Start your project**. Удобнее всего войти через GitHub.
2. **New project**:
   - Name: `mediakarta`;
   - Database Password: придумайте и сохраните в менеджер паролей (в работе он не понадобится, но пусть будет);
   - Region: **Central EU (Frankfurt)**, ближайший к Москве;
   - тариф Free.

   Подождите 1–2 минуты, пока проект создаётся.
3. Слева откройте **SQL Editor** → **New query**. Вставьте целиком содержимое файла `supabase/schema.sql` и нажмите **Run**. Должно появиться `Success`.
4. Слева **Authentication** → раздел с настройками входа (**Sign In / Providers**). Найдите переключатель **Allow new users to sign up** и **выключите** его. Теперь зарегистрироваться самостоятельно нельзя, людей добавляете только вы.
5. **Authentication → Users → Add user → Create new user**:
   - впишите **свою** почту и пароль;
   - поставьте галочку **Auto Confirm User**.

   Первый созданный пользователь автоматически становится администратором, поэтому заводите себя первым.
6. Нажмите кнопку **Connect** вверху (или **Project Settings → API Keys**) и скопируйте два значения:
   - **Project URL**, вида `https://xxxx.supabase.co`;
   - **Publishable key**, вида `sb_publishable_…`. Если такого нет, возьмите **anon public** на вкладке Legacy, он начинается с `eyJ…`.

**Обновления базы.** После `schema.sql` по порядку выполните в SQL Editor файлы обновлений из папки `supabase`: `update-2.0-stage1.sql`, `update-2.0-stage2.sql`, `update-2.0-stage3.sql` и следующие по номеру этапа.

### Шаг 2. Вписать ключи

Откройте файл `js/config.js` любым текстовым редактором и вставьте значения в кавычки:

```js
window.MK_CONFIG = {
  supabaseUrl: 'https://xxxx.supabase.co',
  supabaseAnonKey: 'sb_publishable_xxxxxxxx',
};
```

Этот ключ можно хранить в открытом коде, он для этого и предназначен. Без пароля данные всё равно не прочитать: база пускает только вошедших пользователей.

### Шаг 3. Сайт на GitHub Pages

1. [github.com](https://github.com) → **New repository**:
   - Name: `mediakarta`;
   - **Public**: бесплатный GitHub Pages работает только с публичными репозиториями, а в коде нет никаких данных;
   - нажмите **Create repository**.
2. На странице пустого репозитория нажмите ссылку **uploading an existing file**.
3. Перетащите в окно **всё содержимое** папки `mediakarta`: `index.html`, папки `css`, `js`, `supabase`, файлы `README.md`, `.gitignore`, `.nojekyll`. Скрытые файлы на Mac показываются по Cmd+Shift+. в Finder. Нажмите **Commit changes**.
4. **Settings → Pages**:
   - Source: **Deploy from a branch**;
   - Branch: **main**, папка **/ (root)**;
   - нажмите **Save**.
5. Через 1–2 минуты сайт откроется по адресу `https://ВАШ-ЛОГИН.github.io/mediakarta/`.
6. Вернитесь в Supabase: **Authentication → URL Configuration → Site URL**. Вставьте этот адрес, чтобы ссылки «Забыли пароль?» вели на ваш сайт.

### Шаг 4. Загрузить базу журналистов

1. Откройте сайт и войдите под своей почтой.
2. **Управление → Загрузка базы** → выберите файл `mediakarta_seed.json` из папки `_migration` (он лежит **рядом** с проектом, не внутри) → **Загрузить**. Это займёт 1–2 минуты.

### Шаг 5. Добавить коллег

**Authentication → Users → Add user → Create new user**: почта коллеги, временный пароль, галочка **Auto Confirm User**.

Передайте коллеге адрес сайта и пароль. Пароль он сменит в **Настройках**. После первого входа коллега появится в **Управлении → Пользователи**, и там же ему можно выдать или забрать права админа.

## Как выкатывать обновления

**Вариант А: через сайт GitHub (просто).**
Откройте репозиторий → **Add file → Upload files** → перетащите изменённые файлы с сохранением папок → **Commit changes**. Через минуту обновится сайт.

**Вариант Б: через GitHub Desktop (удобно, если обновлений много).**
1. Установите [GitHub Desktop](https://desktop.github.com) и войдите.
2. **File → Clone repository** → `mediakarta` → выберите папку, например `Desktop/CRM journalist/mediakarta`.
3. Когда файлы в папке поменяются (вы или Claude их обновили), в GitHub Desktop появится список изменений. Впишите в поле Summary пару слов о том, что поменялось → **Commit to main** → **Push origin**.

После обновления нажмите в браузере Cmd+Shift+R (на Windows Ctrl+F5). GitHub Pages иногда кэширует файлы до 10 минут.

## Полезно знать

- **Бэкап.** Раз в месяц делайте **Управление → Выгрузка → Скачать Excel**: это полная копия базы.
- **Пауза бесплатного проекта.** Если в базу никто не заходит неделю, Supabase ставит бесплатный проект на паузу. Данные при этом не теряются: зайдите в панель Supabase и нажмите **Restore project**. При ежедневной работе этого не случится.
- **Права.**
  - Сотрудники видят всё, добавляют и правят контакты, издания, инфоповоды, пишут заметки.
  - Удалять контакты и издания, менять роли, справочники и загружать базу может только админ.
  - Все правки карточек пишутся в «Историю изменений».
- **Защита от двойного питча.** Если журналисту уже писали за последние 7 дней (порог меняется в Управлении), карточка и медиалист покажут предупреждение: кто писал и по какому поводу.
- **Темы оформления.** «Тишина», «Газета», «Пульт». Каждый выбирает свою в **Настройках**, выбор хранится в профиле.

## Устройство (для разработчика)

- Без сборки: Vue 3 и supabase-js подключаются с CDN.
- `js/api.js` — слой данных, реализован в двух вариантах: Supabase и демо.
- `js/app.js` — интерфейс.
- `css/app.css` — три темы на CSS-переменных.
- `supabase/schema.sql` — таблицы, права доступа (RLS), журнал изменений, функция массовой загрузки. Скрипт можно запускать повторно.
